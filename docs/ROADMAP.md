## 0. v3 要解决什么

v2.5.0 上线后复盘：工程骨架可用，但两件事不合格——

1. **领域空心**：只有「掷钱 → 查表」，没有真六爻的装卦体系（纳甲干支、世应、六亲、六兽、旬空、日月建、用神旺衰），解读只有一段白话。「六爻」名不副实。
2. **视觉不达标**：3D 庭院为程序化几何 + Canvas 程序化贴图，日景呈「灰盒」质感；把美术迭代到可发布水准的成本，远超一人项目的承受范围。

已拍板的方向（2026-11-09）：

| 决策 | 结论 | 记录 |
|---|---|---|
| 视觉方向 | 放弃 3D，改 2D 水墨风 | [ADR-0001](adr/0001-replace-3d-with-2d-ink.md) |
| 算法深度 | 补全真六爻装卦体系 | [ADR-0002](adr/0002-full-najia-domain.md) |
| 发布渠道 | 维持 GitHub Pages | — |

## 1. 工作流总览

五个阶段，每个阶段有明确的「出口条件」。**没有出口条件就不进入下一阶段。**

| 阶段 | 做什么 | 产出物 | 出口条件 |
|---|---|---|---|
| **0 立项** | 定义问题、范围、非目标 | PRD / ADR | 方向拍板、决策留痕 |
| **1 设计** | 数据结构、领域模型、界面原型 | 技术方案 + 线框 | 关键决策无未决项（或记为风险） |
| **2 实现** | 按里程碑迭代，每个 PR 一个可验证的增量 | 代码 + 测试 + 文档 | 里程碑验收标准全部满足 |
| **3 审查** | 自审 + 自动化检查 + 真机走查 | 测试报告 + 问题清单 | 发布标准全部满足 |
| **4 发布** | 打 tag、写 CHANGELOG、部署、复盘 | 线上版本 + 复盘记录 | 线上可用 + 回滚方案确认 |

### 日常协作约定

| 项 | 约定 |
|---|---|
| 分支 | `main` 保持可发布；功能 `feat/*`、修复 `fix/*`、文档 `docs/*`、杂务 `chore/*` |
| 提交 | Conventional Commits：`feat:` / `fix:` / `docs:` / `test:` / `chore:` |
| PR | 一个 PR 只做一件事；描述写「改了什么 / 为什么 / 怎么验证」 |
| 合并 | Squash merge，保持 `main` 线性历史 |
| 版本 | SemVer：功能 → MINOR，修复 → PATCH，破坏性 → MAJOR |
| 记录 | 每个版本更新 [CHANGELOG](../CHANGELOG.md)；重要决策写 `docs/adr/NNNN-*.md` |
| Issue | 每个里程碑一组 issue，M0–M4 各一，勾选推进 |
