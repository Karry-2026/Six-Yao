# 视觉与交互规范（v2 重构依据）

这份文档先于动手：所有界面与 3D 改动都对照这里的设计规范、素材来源与审计清单执行。

## 1. 采纳的设计规范

### 1.1 Anthropic `frontend-design` Skill（Apache-2.0）

来源：<https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md>

采纳的硬性规则：

- **从题材出发**：设计要来自「六爻 / 庭院 / 占筮」的材料与语汇，而不是任何页面都能套的模板。
- **字体承载性格**：最多两个字族；标题与正文要有明确分工；不要默认字体。
- **禁止的「AI 味」写法**：标题里只强调一个词、全大写小标签、无意义编号（01/02/03）、每个区块都做 fade-up、每张卡都套同一圆角与灰阴影、用「A · B · C」拼元信息、链接末尾加「→」。
- **动效克制**：只保留一个精心编排的时刻，其余安静；响应式、键盘焦点、降级动效是底线，不是加分项。
- **两遍工作法**：先出 token 方案（4–6 个颜色、字体、布局、原则），再对照「如果换成别的项目会不会也长这样」自我批判，然后才写代码。
- **克制**：只让一个元素成为记忆点，其余退后；出门前摘掉一件配饰。

### 1.2 block/agent-skills `frontend-design`（archived，参考）

来源：<https://github.com/block/agent-skills/blob/main/frontend-design/SKILL.md>

采纳：明确的审美方向、字体要有辨识度、配色要「主导色 + 锐利强调色」、背景要有氛围与材质而非纯色。

### 1.3 其他可选参考

- <https://github.com/alexiseverage/aesthetic-frontend-skills>：把审美拆成 7 个维度的 token（色、字、纹理、形状、动效、空间、文化符号）。
- <https://github.com/TEXXXXTURE/frontend-aesthetic-skill>：token 级约束清单，用于自查。
- WCAG 2.2：对比度、焦点可见、动效可关闭。

## 4. 设计 Token 草案

```
类型：思源宋体（标题/卦辞） + 思源黑体（正文/操作）
字号：12 / 14 / 16 / 20 / 28 / 40（1.25 比例）
行高：正文 1.9；宋体长文 2.0
字距：标题 0.12em；正文 0.02em
间距：4 / 8 / 12 / 16 / 24 / 40 / 64
圆角：0（石材与纸张都是硬边）
阴影：仅一处（石桌接触阴影），不用卡片投影
动效：单一编排时刻（入场推进 + 起卦九秒）；其余只做低频呼吸
```

## 5. 当前版本审计（对照用户反馈）

| 问题 | 现状 | 规范要求 | 处理方向 |
|---|---|---|---|
| 界面不好看 | 玻璃拟态结果卡 + 系统字体回退 | 材质与字体要有依据 | 结果改为「纸上卦签」式面板，宋体为主，去掉玻璃模糊 |
| 硬币悬空 | 铜钱在石桌上方凭空出现/消失 | 起卦发生在桌面 | 镜头改为俯视桌面，铜钱从桌面上方落下、滚动、停住；桌面是主舞台 |
| 打开慢/卡顿 | 首屏加载 3.2 MB，HDRI 与贴图在启动后立即拉取 | 首屏只做海报，3D 空闲加载 | 逐帧截图定位卡点；HDRI 延后到交互后；首帧降分辨率 |
| 结果呈现 | 底部浮动卡片，遮挡场景 | 结果应是场景的一部分 | 卦象与卦名以「卦签/卷轴」形式出现在桌面或侧墙，卡片只保留操作 |

## 6. 实施顺序

1. **性能排查**：用无头浏览器逐帧截图（0.5s 间隔）找出白屏、跳帧、资源竞争的时点；
2. **构图重做**：镜头俯视桌面，铜钱与卦爻都在桌面上完成；
3. **结果重做**：纸上卦签 + 竖排卦名，移除玻璃卡；
4. **字体与配色**：思源宋体子集自托管，按第 3 节色板替换；
5. **验收**：Lighthouse 移动端、键盘走查、真机、逐帧截图对比。

## 7. 自查清单（每次提交前）

- [ ] 这个界面换成别的项目还成立吗？成立就说明太模板。
- [ ] 是否只保留了一个记忆点？
- [ ] 是否有只强调半个标题、全大写标签、无意义编号？
- [ ] 动效是否只有一个编排时刻？
- [ ] 字体是否为项目专门选择，而非默认回退？
- [ ] 对比度、焦点、降级动效是否满足？
- [ ] 新素材是否登记在 `docs/ASSETS.md`？
