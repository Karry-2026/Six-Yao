## 1. 一句话概念

> **一方庭院，一炷香，六次掷币。**
> 用户不是在「浏览一个网站」，而是走进一个安静的院子，在石桌前完成一次起卦。

不是开放世界，不是可漫游的关卡。**固定机位 + 缓慢呼吸感的镜头**，把预算全部花在氛围上。

## 2. 参考与边界

可参考的效果类型（three.js 官方示例可直接对照）：

- `webgl_postprocessing_unreal_bloom`：光晕与灯笼的辉光
- `webgl_shaders_ocean` / `webgl_gpgpu_water`：水面与倒影
- `webgl_points`、`webgl_buffergeometry_custom_attributes_particles`：粒子
- `webgl_postprocessing_godrays`：月光穿过格栅的体积光
- 外部参考：[Daoism Systems](https://dribbble.com/shots/27629962-Immersive-3D-Website-for-a-Web3-Studio-Daoism-Systems)（八卦与鼎的粒子互动）

**明确不做的**：可自由行走的庭院、物理碰撞、加载 50MB 的写实模型、实时多人。

## 3. 场景构成（四层）

| 层 | 内容 | 技术 |
|---|---|---|
| 远景 | 夜色/暮色天空、月、远山剪影 | 渐变 + 噪声 shader，不用贴图 |
| 中景 | 月洞门、白墙、瓦檐、竹林剪影 | 程序化几何 + 实例化 |
| 近景 | 石桌、铜钱、香炉、水面 | 低模 + 材质 shader |
| 前景 | 香火烟、浮尘、萤火、光斑 | GPU 粒子（Points / InstancedBufferGeometry） |

**为什么全部程序化**：模型文件是「必须能跑」的最大敌人——体积大、加载失败就白屏、版权不清。程序化几何 + shader 可以做到 1MB 以内，且没有第三方素材授权问题。

## 4. 镜头与交互

- 默认：固定机位，轻微手持晃动（±0.3°）+ 鼠标/陀螺仪视差（±2°）；
- 滚动：不是翻页，而是**推近**——从院门推到石桌；
- 起卦：镜头下压到桌面视角，铜钱在桌面落定；
- 不做自由旋转，避免用户转到一个没做细节的角度。

## 5. 起卦时刻的分镜

| 阶段 | 画面 | 时长 |
|---|---|---|
| 静 | 香烟上升，水面微动，远处灯笼轻晃 | 循环 |
| 起 | 三枚铜钱从掌心落下，带运动模糊与投影 | 0.8s × 6 |
| 定 | 铜钱落定，桌面刻痕亮起一爻 | 0.4s |
| 成 | 六爻成卦，卦象从桌面浮起，粒子聚拢成形 | 1.2s |
| 读 | 镜头拉回，卦辞以竖排文字浮现在墙上 | — |

动效全部可跳过（`prefers-reduced-motion` 或点击「跳过」）。

## 6. 视觉语言

| 元素 | 选择 |
|---|---|
| 主色 | 墨绿 `#5a8a6a`、米白 `#faf8f4`、朱砂 `#c94040`（点睛） |
| 夜色版 | 深靛 `#10161c`、月白 `#dfe6ea`、暖灯 `#d4a853` |
| 材质 | 哑光石材、旧木、宣纸、青铜；**不用塑料感 PBR** |
| 文字 | 标题宋体（思源宋体子集），正文黑体；竖排用于卦辞 |
| 光 | 一盏主灯（暖）+ 月光（冷）+ 香火点光，最多 3 个动态光源 |

三种氛围，选一个作为 v2.0 的默认：

| 氛围 | 关键词 | 难度 | 适合 |
|---|---|---|---|
| **A. 暮色庭院** | 蓝调时刻、暖灯笼、香烟 | 中 | 最稳，兼顾白天与夜晚 |
| **B. 雨夜** | 雨丝、水面涟漪、湿石反光 | 高 | 最有电影感，但粒子与反射成本翻倍 |
| **C. 雪夜** | 雪粒、呼气白雾、静 | 中 | 最安静，移动端压力小 |

> 建议 **A** 作为 v2.0，B/C 作为主题包留到 v2.1（同一套场景，换光照与粒子参数即可）。

## 7. 技术实现

| 模块 | 方案 |
|---|---|
| 渲染 | three.js（WebGL2），`powerPreference: 'high-performance'` |
| 场景 | 程序化几何；竹林/瓦片用 `InstancedMesh` |
| 粒子 | `Points` + 自定义 shader；香烟用噪声驱动的条带，浮尘用屏幕空间点精灵 |
| 后处理 | `EffectComposer`：Bloom（灯笼/月光）+ Vignette + Film Grain；DOF 仅高档开启 |
| 动画 | 时间轴驱动（自写轻量 tween），不引入 GSAP |
| 字体 | 思源宋体子集自托管（**不用 Google Fonts**，见 §9） |

## 8. 性能分级与降级

启动时探测：`WebGL2` 可用性、`devicePixelRatio`、屏幕尺寸、`navigator.hardwareConcurrency`、`navigator.deviceMemory`。

| 档位 | 条件 | 表现 |
|---|---|---|
| **High** | 桌面 + 独显/高分屏 | 全特效：Bloom + DOF + 2000 粒子 + DPR 2 |
| **Medium** | 桌面核显 / 高端手机 | 去 DOF，粒子 800，DPR 1.5 |
| **Low** | 中低端手机 | 去后处理，粒子 300，DPR 1，静态阴影 |
| **Off** | 无 WebGL2 / 用户开启省电 / 减少动态 | **静态海报页**（同一构图的高清图 + 2D 交互），功能完整 |

**Off 档不是阉割版**：起卦、推演、解读、历史全部可用，只是没有 3D。这是「必须能跑」的底线。

## 9. 「必须能跑」的四条硬保障

1. **子路径正确**：站点部署在 `/Six-Yao/`，Astro 配置 `base: '/Six-Yao'`，所有资源用 `import.meta.env.BASE_URL` 拼接；CI 里用本地服务器挂到 `/Six-Yao/` 跑一遍，断言没有 404。
2. **不依赖外部 CDN**：字体、three.js 全部打进产物；不引用 Google Fonts / unpkg / jsDelivr（国内经常加载失败）。
3. **失败可降级**：WebGL 上下文创建失败、shader 编译失败、帧率连续 2 秒低于 20fps → 自动降档，最低降到静态海报。
4. **自动化冒烟**：Playwright 用 SwiftShader 跑一遍构建产物，断言 canvas 存在、无未捕获异常、无 404；截图存档作为视觉回归基线。

## 10. 资产与版权

- **默认零外部资产**：几何、贴图、噪声全部代码生成；
- 如确需贴图，只用 **CC0**（如 [Poly Haven](https://polyhaven.com/license)），并在 `docs/ASSETS.md` 记录来源、许可证、下载日期；
- **不使用**来源不明的「公开美术资源」、AI 生成但授权不清的贴图、他人站点扒下来的模型；
- 字体使用开源字体（思源宋体/黑体，SIL OFL），子集化后自托管。

## 11. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 移动端 GPU 发热降频 | 卡顿 | Low 档 + 帧率监测自动降档 |
| iOS Safari 的 WebGL 限制 | 黑屏 | 启动探测 + 静态兜底 + 真机测试 |
| 3D 拖慢首屏 | 用户流失 | 先出静态海报，3D 延迟加载（`requestIdleCallback`） |
| 范围膨胀 | 做不完 | v2.0 只做一个氛围（A），B/C 进 v2.1 |
| 无障碍倒退 | 键盘用户无法操作 | 3D 只是表现层，DOM 交互始终存在 |
