## 1. 背景

v1 是一个 81 KB 的单文件页面：能起卦、能推演本卦/互卦/变卦、能看解读、能存历史。它证明了「想法可以落地」，但存在四个明确问题：

1. **结构不可维护**：1350 行里 HTML、CSS、JS、64 卦数据混在一起，改一处要看三处；
2. **正确性无验证**：互卦、变卦的推演是最容易出错的逻辑，却没有任何测试；
3. **体验停在上一个时代**：无深色模式、结果无法分享、无离线能力、动效不尊重系统设置（v1 后期已补这一条）；
4. **内容可信度未声明**：卦辞来源、白话解读是否 AI 生成、是否校对过，页面没有交代。

v2 的目标不是「换个好看的皮」，而是把 v1 变成一个**工程上站得住、内容上说得清**的项目。

## 2. 目标与非目标

### 目标

- **G1** 结构可维护：数据、算法、视图分离，新增一卦不需要改三处；
- **G2** 算法可验证：起卦与推演有单元测试，分布有统计验证；
- **G3** 体验现代化：移动优先、深色模式、可分享、可离线、尊重无障碍设置；
- **G4** 内容可追溯：标注文本来源与 AI 参与程度，提供校对记录；
- **G5** 发布可复现：CI 自动构建、测试、部署，任何人可复现线上版本。

### 非目标（本版不做）

- ❌ 账号体系、云端同步（涉及后端与隐私，v2 保持纯静态）；
- ❌ 付费、广告、任何商业化；
- ❌ 在线解卦问答 / AI 对话（会把项目拖进后端与成本问题）；
- ❌ 社区、评论、UGC；
- ❌ 多语言全量翻译（先保留中文，英文版作为 v2.1 候选）。

## 5. 随机性与内容可信度（本项目的技术核心）

这是最容易被质疑的部分，必须写清楚。

### 5.1 掷币模型

传统三枚铜钱法：每枚铜钱正反各 50%，三枚之和决定一爻。

| 结果 | 数值 | 概率 | 爻性 |
|---|---|---|---|
| 三正 | 9 | 1/8 | 老阳（动爻） |
| 两正一反 | 8 | 3/8 | 少阴 |
| 一正两反 | 7 | 3/8 | 少阳 |
| 三反 | 6 | 1/8 | 老阴（动爻） |

### 5.2 随机源

v2 使用 `crypto.getRandomValues`（CSPRNG），**不是 `Math.random`**。每次掷币取一个无偏随机位。

但必须诚实：**这仍然是伪随机**——由操作系统熵池驱动，不可预测，但并非物理随机。页面不会宣称「真随机」或「通灵」，只会宣称「符合古典掷币模型的均匀分布」。

### 5.3 可验证性

- **可复现**：分享链接携带六次掷币结果，任何人打开都能得到完全相同的卦；
- **可统计**：对 RNG 与卦象生成跑 10 万次，卡方检验验证 1:3:3:1 的分布；
- **可手动**：不信任自动掷币的人，可以自己掷铜钱后录入。

### 5.4 内容来源

| 内容 | 来源 | 状态 |
|---|---|---|
| 卦名、卦序、上下卦 | 《周易》通行本 | 需逐条校对（见 ROADMAP M1） |
| 卦辞、象辞 | 公有领域古籍 | 需与通行本比对 |
| 白话解读 | AI 生成 + 人工校对 | 页面标注「AI 辅助撰写，已人工校对」 |

**不做**：不宣称预测能力，不提供医疗、法律、投资建议；保留并强化免责声明。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 可访问性 | 键盘可完成全部操作；对比度 ≥ WCAG AA；尊重 `prefers-reduced-motion` |
| 性能 | 移动端 4G 首屏 LCP < 2.5s；Lighthouse Performance ≥ 90 |
| 体积 | 首屏 JS ≤ 50 KB（gzip）；字体按需加载 |
| SEO | 每卦有独立静态页与 `title`/`description`；sitemap；OG 图 |
| 隐私 | 无第三方追踪 cookie；不收集个人信息；分享链接不含身份信息 |
| 安全 | 分享参数白名单校验；不使用 `innerHTML` 渲染用户输入 |
| 兼容 | 最近两个版本 Chrome/Edge/Safari/Firefox；iOS Safari 可用 |

## 7. 成功标准（Definition of Done）

一个版本只有全部满足才算「发布」：

1. P0 功能全部通过验收；
2. 核心算法单测覆盖 ≥ 90%，全部 64 卦推演用例通过；
3. CI 绿灯（lint + typecheck + test + build）；
4. Lighthouse（移动端）Performance / Accessibility / Best Practices ≥ 90；
5. 无控制台报错；无未处理的 Promise rejection；
6. CHANGELOG 已更新，版本号已打 tag；
7. 线上地址实测可用（桌面 + 手机）；
8. 回滚方式明确（回退到上一个 tag）。

## 8. 风险与未决问题

| 风险 | 影响 | 应对 |
|---|---|---|
| 64 卦文本校对工作量大 | 内容出错，可信度受损 | 先做数据校验脚本（结构/卦序/上下卦），文本分批校对 |
| 分享链接被滥用/注入 | XSS | 参数白名单 + 长度限制 + 不使用 innerHTML |
| 过度设计导致做不完 | 项目烂尾 | 锁定 P0 范围，P1/P2 可砍 |
| 国内访问 `github.io` 不稳 | 用户打不开 | 文档注明；必要时加自定义域名或镜像 |

**未决问题（需要作者拍板）**：

- Q1：是否保留 v1 的视觉风格（米白 + 墨绿），还是走更现代的极简？
- Q2：英文版是否纳入 v2.0，还是留到 v2.1？
- Q3：是否需要自定义域名（影响「正式感」与国内可访问性）？
